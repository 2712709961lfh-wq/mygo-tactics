# 第一关地图重制与项目分析

> 本文记录 v2.0 的历史版本。当前 v4.1 地图为 36×24、18 名敌人，最新设计与授权见 [FATES-MAP-REMAKE.md](FATES-MAP-REMAKE.md)。

本次修改针对第一关「黄昏的迷途庭院」。地图尺寸为 24×16，格子为 32px，保留五名我方、六名敌方以及夺钥匙、开门、唤醒内庭敌人的流程。原关卡源文件已保存在 `backups/before-stage-one-remake.zip`。

## 项目文件梳理

项目是原生 HTML / CSS / JavaScript 的 Canvas 战棋，无 npm 运行依赖。不是 Unity、Godot 或 RPG Maker 工程。`index.html` 使用经典 script 加载，可直接双击运行；`standalone.html` 是生成产物，必须通过 `build-standalone.js` 同步更新。

| 文件组 | 内容与判断 |
| --- | --- |
| `index.html`、`styles.css`、`entry.css` | 主页面、战斗 UI、标题与编队界面。地图放在支持滚动和缩放的 Canvas 视口内。 |
| `src/config.js` | 武器、地形、两章地图、角色模板、关卡目标。原第一关行长不一致，依靠补齐和截断修正，出生格又被自动改成草地，容易掩盖编辑错误。重制版使用严格的 24 列地图。 |
| `src/grid.js`、`pathfinding.js`、`combat.js`、`rng.js` | 网格、Dijkstra 移动范围、物魔战斗与可保存的随机数。可独立于浏览器运行测试。 |
| `src/game.js`、`ai.js`、`save.js` | 对局状态、敌方计划和存档。大门按地形 id 全图同步；钥匙守卫死亡后开门。原 AI 用曼哈顿距离趋近目标，在隔河绕行时会停住，本次补充通路距离。 |
| `src/assets.js` | 原有地形贴图、建筑装饰、影子敌人和程序绘制兜底。第二关继续使用原有地形画笔。 |
| `src/characters.js`、`character assets/`、`assets/characters/` | 原图、绿幕行走、四向待机、整理后的动作图集与肖像。地图与战斗使用不同尺寸和姿态。原有角色素材保持使用。 |
| `src/renderer.js` | 地形缓存、高亮、单位、血条、钥匙标记、粒子。原来大建筑覆盖了未被建筑实际占用的格子，门图还偏离真正的门格。重制版从实际地形绘制岸线与墙体，门严格覆盖两格门洞。 |
| `src/ui.js`、`entry.js`、`main.js` | 输入与行动状态机、标题/编队/存档抽屉、启动预载。另修复启动时 `MYGO.ui` 大小写错误造成的异常，应为 `MyGO.ui`。 |
| `src/battle.js`、`battle-preview.html`、`battle-integration.html` | 侧视战斗演出与独立调试页。与地图渲染解耦。 |
| `tools/prepare-*.py` | 对角色图进行去背、裁切、尺寸规整。无需为地图重制重新执行。 |
| `map_assets/raw/`、`raw2/`、`castle-bg.jpg` | 旧地图导出图及背景，包含重复文件和非透明棋盘背景。已通过图片清单检查，原有素材保留。 |
| `item assets/`、根目录旧截图 | 透明物件图、旧地图和游戏效果记录。本次未把截图直接当成新地图底图。 |
| `tests/test-core.js` | 原有 38 项核心回归；本次更新旧地图坐标，并增加地图连通、AI 绕桥、存档地图版本三项检查。 |
| `README.md`、`DEPLOY.md`、`docs/DESIGN.md`、`docs/ASSETS.md`、打包脚本与 bat | 项目运行、部署、架构、素材替换和单文件分享说明。 |

图片浏览清单：`previews/original-assets-contact.jpg`。重复导出图、历史截图和 Python 字节码不属于本次地图运行必需项，未据此删除用户文件。

## 地图布局与玩法

1. **西南集结草坪**：五人以两层阵形出发，接近南侧主桥。旁边有树林与岩地，分别提供闪避和物理守备。
2. **西北礼拜堂与北桥**：礼拜堂全部落在不可通行的建筑格。沿树林小路可向北桥推进，对西侧影刃形成接敌路线。
3. **纵向水渠与两组桥**：水渠宽两格，北桥位于第 7–8 行，南桥位于第 12–13 行。每组桥宽两格，降低单个单位封死过桥通路的概率。水与桥的画面逐格对应地形规则。
4. **东庭钥匙守卫**：南桥连接东西向花园主路，影斧、影刃和携带钥匙的影弓依次分布。外围敌人沿用主动接近玩家的行为，因此守卫不会被强制钉在出生点。
5. **北侧封闭内庭**：城墙完整包围石坪；只有南侧两格大门能进入。中央喷泉占四格深水，两侧有花坛树林，首领与影枪分处内庭前后。开门后苏醒。

所有坐标使用从零开始的 x/y：南门 `(16,8)`、`(17,8)`；钥匙守卫出生 `(21,11)`；首领出生 `(16,2)`。整张地图开门后不存在孤立的可通行格。

| 地形 | 移动消耗 | 闪避 | 守备 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 草地 / 花园小径 / 内庭石坪 | 1 | 0 | 0 | 小径和石坪有独立地形名称，鼠标查看时能正确显示。 |
| 森林 | 2 | +20 | 0 | 可通行的树丛，单位可利用掩护。 |
| 山地（画面为低矮岩地） | 2 | 0 | +3 | 守备只影响物理伤害，沿用原战斗公式。 |
| 水 / 城墙 / 关闭的门 | 不可通行 | — | — | 画面与寻路一致。 |
| 木桥 / 开启的门 | 1 | 0 | 0 | 原 bridge 规则在第二关仍显示石桥；第一关通过地图绘制表现为木桥。 |

## 美术与外部参考

实际引入的开源素材为 Kenney 发布的 CC0 美术，两张图集均已保存在项目内，运行时无需联网：

- [Tiny Town](https://kenney.nl/assets/tiny-town)，版本 1.1。使用树木、城墙砖面、窗户和门。原始图集与许可证：`assets/terrain/kenney/tiny-town/tilemap_packed.png`、`License.txt`。
- [Tiny Dungeon](https://kenney.nl/assets/tiny-dungeon)，版本 1.0。使用喷泉中心的发光石制装饰。原始图集与许可证：`assets/terrain/kenney/tiny-dungeon/tilemap_packed.png`、`License.txt`。
- [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/) 允许个人、教育与商业使用，无强制署名要求；项目仍保留 Kenney 来源与原始许可证。
- [Serenes Forest 地形资料](https://serenesforest.net/the-sacred-stones/miscellaneous/terrain-data/) 用作火纹类游戏“移动成本与防守收益分开呈现”的设计参考。未导入商业游戏地图或素材。

水渠、岸边、木桥、低矮岩地、花园小路、庭院石坪、礼拜堂屋顶、大门及整体布局由项目代码原创绘制。参考了 Kenney 发布页的素材拼接方式；本次地图结构独立设计。配色采用苔绿、灰蓝石墙、低饱和水色和少量秋叶金色，避免原图多套生成素材混用的尺度差异。

新增模块 `src/garden-map.js` 从 `map.tiles` 读取每一格，计算岸线、墙缘和桥栏。静态画面缓存一次；门状态独立绘制。素材加载失败会回退到程序画笔，第一关的阻挡判定不依赖图片加载成功。

## 预览、打包与验证

- 双击 `map-preview.html`：纯地图、单位部署、门状态切换、PNG 导出；预览不读取或写入游戏存档。
- 双击 `index.html`：正常进入第一关。
- `node build-standalone.js`：生成内嵌新增素材与脚本的 `standalone.html`，图片 MIME 按 PNG / JPEG 正确区分。
- `node tests/test-core.js`：41 项通过，包括原战斗公式、第二关河桥与读档，以及新增地图检查。
- `tools/render-map-preview.js`：可用工作区运行时的 `@napi-rs/canvas` 离线输出三张高清预览；它直接运行真实渲染代码，图片位于 `docs/previews/`。

第一关旧存档使用旧地图坐标，重制后可能落进水渠或建筑，无法安全直接迁移。为此存档增加 `mapRevision: 2`，旧第一关存档会提示重开，未主动删除或覆盖。新地图存档正常往返；第二关旧存档继续支持。
