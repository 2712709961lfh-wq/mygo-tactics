# 第一关钥匙与通关招募

更新日期：2026-11-12。

## 钥匙开门

- 第一关钥匙影弓被击败后，内庭钥匙放入实际击败者的背包。敌方回合中的反击击败也归反击者。
- 钥匙占用一个背包格。满五格时，自动把一件未装备物品存回运输队，为钥匙腾位；掉落提示会说明腾位物品。
- 大门不会因守卫被击败自动打开，内庭敌人仍保持休眠。
- 持有者移动到门的上下左右相邻格时，弹出「使用内庭钥匙开门？」。取消不消耗钥匙或行动，行动菜单仍可再次选择开门。
- 确认使用需要我方阶段、角色存活且未行动。成功后消耗钥匙、结束角色本次行动，并同步开启整座内庭门与内庭敌人的行动权限。
- 钥匙显示在「同行之人 → 背包配置」，不能作为装备；可按现有背包规则存入运输队，再由其他角色领取。
- 钥匙归属、运输队物品和开门状态均随存档保存。旧版已经开启的门保持开启。

## 雪月招募

- 雪月在第一关被击败后保持退场，第一关不会变成我方可操作单位。
- 即使提前击败雪月，也必须继续击败全部剩余敌人，才能通关并解锁招募。
- 第一关通关后播放雪月招募演出，包含卡片淡入、肖像显现和对白；点击「一起前行」后显示胜利结算。
- 第一关通关结算仍统计本关五名我方角色；进入第二关后雪月以满生命、未行动的第六名同伴出战。
- 招募状态和已观看状态分别保存。读取已确认招募的通关档不会重复播放；尚未确认的通关档会补播。
- 旧版在第一关中途已经入队的雪月，读档后转换成已击败退场状态，通关后招募；旧版通关档保留解锁第二关的资格。
- 直接从标题开始第二关、且没有第一关通关招募记录时，沿用原行为，不提前解锁雪月。

## 验证

运行 `node tests/test-progression.js`，检查钥匙实际归属、非致命与重复结算、满背包腾位、门旁使用条件、消耗与读档、运输队转交、雪月提前击败后的通关判定、旧档迁移、移动后自动弹窗、取消与再次确认、招募与胜利弹窗顺序、观看状态保存。

核心与反击测试已同步新规则，运行 `node tests/test-core.js`、`node tests/test-counterattack.js`。背包和 UI 原有回归分别为 `node tests/test-inventory-magic.js`、`node tests/test-ui-flow.js`。

招募流程的独立人工验收入口为 `index.html?recruit-demo=1`，使用内存存档；击败邻近的一血雪月即可触发通关与招募，不影响正式存档。
